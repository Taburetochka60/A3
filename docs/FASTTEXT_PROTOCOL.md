## Additional from-scratch subword arm

D (`fasttext_subword`) keeps every A/B hyperparameter and the same initial FastText vocabulary matrix as B. It replaces NER-vocabulary UNK with normalized vectors from the verified official binary, during **both fit and inference**. This includes rare fit words outside the 30000-word cap. Dictionary hits use `get_word_vector`; dictionary misses use the binary's genuine five-character subwords. Zero outputs stay zero. Known word rows are trainable, as in B. External OOV vectors are fixed, carry no NER-trained parameters and never consume evaluation labels. D is a representation comparison, not an initialization-only control. Its recurrent/classifier initialization must equal B's.

Routing IDs cover fit and requested evaluation tokens without learning a vocabulary from evaluation. Their cache is content-addressed by official binary SHA, baseline vocabulary and exact keys. Future inference requires a verified cache for all requested tokens; missing keys fail, never silently become UNK. The large binary is released after cache preparation. A nonpersistent GPU buffer holds fixed OOV rows (1200 bytes per distinct key); checkpoints pin the cache hashes and require it for reconstruction. Trainable parameter count equals B, while buffer bytes are reported separately.

## Question and controls

Does Ukrainian FastText initialization improve a fresh word BiLSTM compared with random initialization? A and B both use the frozen 100000 fit rows, 4000 checkpoint rows and 2000 calibration rows. No audit, organizer or file-origin/domain-classification labels train or select these NER models. Test labels are never read. All protected evaluation rows remain in surface-set scoring, including four BIO-incompatible rows per development partition; only their token loss is undefined.

A: random 300-dimensional word embeddings. B: official `cc.uk.300.bin`, Common Crawl/Wikipedia Ukrainian vectors, 300 dimensions. Both embeddings are trainable from epoch 1. Both use the same fit-only 30000-word vocabulary and NFC/casefold keys. Each nonzero embedding row is normalized to unit length before training, including the random control, to control scale. PAD is zero and UNK is the same seeded random unit vector in both models. FastText zero outputs stay zero and are reported, never replaced with random vectors.

Both: seed 42; two bidirectional LSTM layers; hidden size 64 per direction; embedding size 300; dropout .2 before/after the encoder and between layers; three BIO outputs; AdamW LR .002, weight decay .01, betas .9/.999, eps 1e-8; batch 128; gradient clipping 1; at most 15 epochs, patience 6. Keep the successful depth/hidden size/budget; changing hidden size or adding a scheduler would confound initialization. Scheduler is deliberately none. Weighted masked cross-entropy and class weights fit only on fit labels. Use the existing 128-token windows, overlap 32, packed sequences and deterministic bucketing. Native BF16 if supported, otherwise FP16/GradScaler; numerical fallback is explicit and recorded for both arms. Deterministic algorithms are required; unsupported GPU kernels fail visibly.

Recurrent and classifier initialization hashes must match between A and B. Neither arm loads any n-grams model weights. The n-grams checkpoint `ed3c9e14bba969a129d3f70e670e05b968815bb93e4586fb1161cc0f7afeaa29` is a read-only historical comparator. Its 64-dimensional word+n-gram input differs from A/B, so C is not an initialization-only control. The rejected domain-format candidate is excluded.

## FastText provenance and OOV

Official page: https://fasttext.cc/docs/en/crawl-vectors.html
Official file: https://dl.fbaipublicfiles.com/fasttext/vectors-crawl/cc.uk.300.bin.gz
Model: CBOW position weights, 300 dimensions, five-character subwords, 2018 release (server Last-Modified 2019-01-18). License: CC BY-SA 3.0; cite Grave et al., LREC 2018. Code uses the official `fasttext==0.9.3` bindings.

Observed HEAD: 4504123670 compressed bytes (4.19 GiB). A range read confirmed magic 793712314/version 12, 2000000 dictionary words and 2000000 subword buckets. Float matrices alone need 7200000000 bytes (6.71 GiB), plus dictionary/loader/data memory. Plan roughly 10-12 GiB available host RAM and 15 GiB local disk; use High-RAM only if the measured host-memory check requires it. Cache the compressed official model on Drive once. Build small fit matrices and diagnostic OOV vectors on CPU, then release the large model before GPU training. CPU preparation before switching to a GPU saves Compute Units.

No vendor SHA256 is published on the model page. The first complete HTTPS download pins its actual SHA256, length, URL and headers; subsequent cache use verifies them. The binary header, dimensions, known-word probes and actual vectors must pass before either arm trains. Download/loading failures stop preparation; there is no random fallback. Record dictionary hit coverage, subword-generated coverage and zero-vector counts. A toy binary tests the loader locally; full official loading is only verified after real Colab preparation.

Primary A/B collapse NER-vocabulary OOV tokens to their common UNK, preserving an initialization-only comparison. The binary's subword mechanism still supplies initial vectors for fit-vocabulary words absent from its external dictionary. A separate, preregistered **inference-only diagnostic** may replace B's NER-OOV vectors with frozen FastText subword vectors after epoch selection. It changes OOV handling beyond initialization, is labeled separately, and cannot select epochs or replace the primary result. Routing IDs for diagnostic keys are not fitted vocabulary entries.
